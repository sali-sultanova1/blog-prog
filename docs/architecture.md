# Архитектура проекта

Проект представляет собой новостной блог на Django. Функциональность разделена между несколькими приложениями, чтобы не смешивать работу с пользователями, статьями и пользовательскими взаимодействиями.

## Приложения

### `accounts`

Отвечает за пользователей и профили:

- кастомная модель `CustomUser`;
- регистрация и вход;
- вход по username или email;
- редактирование профиля;
- профиль автора;
- переход пользователя в роль автора.

### `articles`

Основная логика публикаций:

- статьи;
- категории и теги;
- создание и редактирование статей;
- статусы публикации;
- отправка на модерацию;
- очередь модерации;
- история решений модератора;
- поиск и фильтрация;
- REST API для статей, категорий и тегов.

Статья проходит состояния:

```text
draft → submitted → published
                  ↘ rejected → редактирование → submitted
```

Опубликованную статью нельзя редактировать через обычный авторский workflow.

### `interactions`

Отвечает за взаимодействие пользователей с опубликованными статьями:

- комментарии;
- лайки;
- закладки;
- REST API для комментариев.

Лайки, закладки и работа с комментариями на странице статьи выполняются через API и JavaScript без полной перезагрузки страницы.

### `core`

Содержит общую конфигурацию проекта:

- `settings.py`;
- корневую маршрутизацию;
- маршруты API;
- middleware;
- обработчики ошибок 400, 403, 404 и 500.

## Данные и инфраструктура

Основная база данных — PostgreSQL.

Redis используется для кеширования списка категорий и тегов. При их изменении соответствующий кеш очищается через Django signals.

Статические файлы собираются через `collectstatic`, для их обслуживания настроен WhiteNoise. Загруженные пользователями изображения хранятся отдельно в `media/`.

## Контроль доступа

В проекте используются стандартные permissions Django и группа `Authors`.

- Гость может читать опубликованные статьи.
- Зарегистрированный пользователь может взаимодействовать с публикациями.
- Автор получает права на создание и управление своими статьями.
- Staff-пользователь имеет доступ к модерации.

Права также проверяются на уровне REST API, поэтому ограничение доступа не зависит только от интерфейса.
