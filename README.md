# News Platform

Учебная новостная платформа на Django с системой ролей, публикацией и модерацией статей, комментариями, лайками, закладками, REST API, PostgreSQL, Redis, Docker и автоматическими тестами.

Проект реализует полный цикл публикации материала: зарегистрированный пользователь может стать автором, создать черновик, отправить его на модерацию, а сотрудник сайта — одобрить или отклонить публикацию. Читатели могут просматривать опубликованные статьи, пользоваться поиском и фильтрацией, ставить лайки, сохранять статьи и участвовать в обсуждении.

## Возможности

### Пользователи и роли

В проекте предусмотрено несколько уровней доступа:

- **Гость** — может просматривать опубликованные статьи, пользоваться поиском и фильтрами.
- **Зарегистрированный пользователь** — дополнительно может редактировать профиль, ставить лайки, сохранять статьи и оставлять комментарии.
- **Автор** — может создавать статьи, редактировать свои материалы и отправлять их на модерацию.
- **Сотрудник / администратор** — может модерировать отправленные статьи и принимать решение о публикации.

Войти в аккаунт можно как по **имени пользователя**, так и по **email**.

## Жизненный цикл статьи

Статья проходит несколько состояний:

```text
Черновик
   ↓
Отправлена на модерацию
   ↓
Модерация
   ├── Опубликована
   └── Отклонена
          ↓
     Редактирование
          ↓
     Повторная отправка
```

Автор может:

- создать статью;
- указать заголовок, slug, краткое описание и основной текст;
- загрузить обложку;
- выбрать категории и теги;
- редактировать черновики и отклонённые статьи;
- отправлять статью на модерацию;
- удалять собственные статьи;
- отслеживать статус своих материалов.

Сотрудник сайта может:

- открыть очередь модерации;
- просмотреть отправленную статью;
- опубликовать или отклонить её;
- добавить комментарий модератора;
- сохранить запись о результате модерации.

## Взаимодействие с публикациями

Авторизованный пользователь может:

- поставить или убрать лайк;
- добавить или удалить статью из закладок;
- оставить комментарий;
- отредактировать свой комментарий;
- удалить свой комментарий;
- открыть профиль автора.

Лайки, закладки и комментарии работают через REST API без полной перезагрузки страницы.

## Поиск и фильтрация

На главной странице реализованы:

- текстовый поиск;
- фильтрация по категориям;
- фильтрация по тегам;
- динамическое обновление результатов через API;
- пагинация.

Публично отображаются только статьи со статусом `PUBLISHED`.

## Профили авторов

На странице автора отображаются:

- информация о пользователе;
- опубликованные статьи;
- количество опубликованных материалов;
- общее количество лайков;
- общее количество комментариев.

## Интерфейс

В проекте есть:

- обложки статей;
- страницы регистрации и входа;

## REST API

Проект использует Django REST Framework.

Основные API-маршруты:

```text
/api/articles/
/api/categories/
/api/tags/
/api/comments/
```

JWT-аутентификация:

```text
/api/token/
/api/token/refresh/
```

Документация API:

```text
/api/docs/
/api/schema/
```

API учитывает основные правила проекта: права пользователей, статусы публикаций, принадлежность комментариев и ограничения на изменение опубликованных материалов.

### Назначение приложений

`accounts` отвечает за пользователей, регистрацию, аутентификацию, профили и авторские профили.

`articles` содержит основную логику публикаций: статьи, категории, теги, статусы, модерацию, фильтры, API и права доступа.

`interactions` отвечает за взаимодействия пользователей со статьями: комментарии, лайки и закладки.

`core` содержит глобальные настройки Django-проекта, маршрутизацию, middleware, маршруты API и обработчики ошибок.

Такое разделение позволяет не смешивать логику пользователей, публикаций и пользовательских взаимодействий в одном приложении.

## Запуск проекта

### Требования

Для запуска необходимы:

- Git
- Docker
- Docker Compose

Клонирование репозитория:

```bash
git clone https://github.com/sali-sultanova1/blog-prog.git
cd blog-prog
```

Создание локального файла переменных окружения:

```bash
cp .env.example .env
```

Сборка и запуск контейнеров:

```bash
docker compose up -d --build
```

Применение миграций:

```bash
docker compose exec web python manage.py migrate
```

Создание администратора:

```bash
docker compose exec web python manage.py createsuperuser
```

После запуска сайт доступен по адресу:

```text
http://localhost:8000/
```

Django Admin:

```text
http://localhost:8000/admin/
```

Swagger:

```text
http://localhost:8000/api/docs/
```

## Переменные окружения

Настройки проекта загружаются из `.env`.

Пример:

```env
DJANGO_SECRET_KEY=change-me
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1

POSTGRES_DB=blog_db
POSTGRES_USER=blog_user
POSTGRES_PASSWORD=change-me
POSTGRES_HOST=db
POSTGRES_PORT=5432

REDIS_URL=redis://redis:6379/1

EMAIL_HOST_USER=your-email@yahoo.com
EMAIL_HOST_PASSWORD=your-app-password
DEFAULT_FROM_EMAIL=your-email@yahoo.com
```

Настоящий файл `.env` добавлен в `.gitignore` и не должен попадать в репозиторий.

## Тестирование

В проекте находится **23 автоматических теста**:

- 2 теста авторизации;
- 7 интеграционных тестов web-части;
- 11 интеграционных тестов REST API;
- 2 unit-теста сериализатора комментариев;
- 1 системный тест полного жизненного цикла статьи.

Полный запуск тестов:

```bash
docker compose exec web python manage.py test
```

Дополнительные проверки:

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py migrate --check
```

## Системный тест

Отдельный системный тест проверяет полный сценарий работы с публикацией:

```text
Авторизованный пользователь
        ↓
Становится автором
        ↓
Создаёт черновик
        ↓
Отправляет статью на модерацию
        ↓
Сотрудник публикует статью
        ↓
Статья становится доступна публично
```

## GitHub Actions

В проекте настроен CI workflow:

```text
.github/workflows/tests.yml
```

При `push` и `pull_request` GitHub Actions:

1. клонирует репозиторий;
2. создаёт `.env` из `.env.example`;
3. собирает Docker-образ приложения;
4. запускает PostgreSQL и Redis;
5. запускает автоматические тесты.

## Статические и пользовательские файлы

Статические CSS и JavaScript-файлы находятся в:

```text
static/
```

Для обработки собранных статических файлов используется WhiteNoise.

Файлы, загружаемые пользователями, например аватары и обложки статей, сохраняются в:

```text
media/
```

Папка `media/` не хранится в Git.

Для полноценного production-развёртывания пользовательские media-файлы необходимо обслуживать отдельным веб-сервером или объектным хранилищем.

## Безопасность

Секретные значения хранятся в переменных окружения, а настоящий `.env` исключён из Git.

Для production необходимо использовать:

```env
DJANGO_DEBUG=False
```

Также в production должны быть отдельно настроены HTTPS, безопасные cookies, разрешённые домены и обслуживание media-файлов.

Текущая Docker Compose-конфигурация предназначена прежде всего для локальной разработки, демонстрации и проверки учебного проекта.
